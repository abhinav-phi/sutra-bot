### Measured LLM-provider facts to honor in every phase (2026-09-01)

From the api.b.ai bake-off ([`9. ModelBench.md`](9.%20ModelBench.md)) — these are constraints, not preferences:

- **Per-key rolling rate limit ≈ 9–10 req/min.** Any script (bench, load test, simulator) must dispatch sequentially with ≥6.5s pacing and 429 backoff (10/25/45s). The 255-push warmup (L-10) is unaffected (no LLM calls); tick-time top-K parallel composition leans on the cache instead of parallel provider calls.
- **All six models are reasoning models.** `max_tokens ≥ 1500–2000` for composer calls; empty `content` + `finish_reason="length"` = model failure → secondary → templates (wired into the three-tier path).
- `glm-5.3-flash` additionally throws transient "model busy" 429s — one retry minimum on 429 regardless of pacing.
