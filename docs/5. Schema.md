# Schema — Sutra

## 1. Data Architecture

**In-memory first** with optional single-file disk snapshot for restart recovery.

**Justification:**
- Test window is 60 minutes; in-memory is sub-millisecond.
- 255 base contexts + 100 triggers + ~240 actions + ~60 replies = small footprint (<50 MB).
- Atomic disk snapshot (temp-file + rename) every 30s survives restarts.
- No DB server adds latency, connection management, schema migrations.

**Snapshot file:** `disk_snapshot.sutra` — single file, atomic write (temp + rename), JSON or pickle format.

## 3. Entities (full field tables)

### 3.1 ContextRecord

| Field | Type | Description | Validation |
|---|---|---|---|
| `scope` | `EnumScope` | One of category, merchant, customer, trigger | Required |
| `context_id` | `str` | Unique within scope | Required, non-empty |
| `version` | `int` | Monotonically increasing per (scope, context_id) | Required, ≥ 1 |
| `payload` | `dict` | The context payload (per challenge schema) | Required, ≤ 500 KB |
| `received_at` | `datetime` | When this version was stored | Required, ISO 8601 UTC |

**Invariants:**
- `(scope, context_id)` is the primary key.
- `version` is monotonically increasing per key.
- Higher version atomically replaces lower.
- Same version is no-op.
- Lower version returns 409.

### 3.2 ConversationState

| Field | Type | Description | Validation |
|---|---|---|---|
| `conversation_id` | `str` | Unique conversation identifier | Required, decodable (e.g., `conv_{merchant_slug}_{trigger_kind}_{week}_{seq}`) |
| `merchant_id` | `str` | Merchant identifier | Required |
| `customer_id` | `str \| None` | Customer identifier (if customer scope) | Nullable |
| `send_as` | `EnumSendAs` | `vera` or `merchant_on_behalf` | Required |
| `language` | `str` | Primary language (from `identity.languages[0]` or `customer.identity.language_pref`) | Required |
| `turns` | `list[Turn]` | Conversation turns (both sides) | Required, ≤ 5 |
| `topics_sent` | `set[(str, str)]` | Set of `(trigger_kind, signal_id)` already sent in this conversation | Required |
| `body_hashes` | `set[str]` | Set of normalized body hashes for verbatim detection | Required |
| `last_merchant_reply_at` | `datetime \| None` | Timestamp of last merchant/customer reply | Nullable |
| `ended` | `bool` | Whether conversation has ended | Required, default False |
| `ended_reason` | `str \| None` | Reason for ending (e.g., "merchant requested stop") | Nullable |
| `wait_until` | `datetime \| None` | If in wait state, when wait expires | Nullable |
| `nudge_count` | `int` | Number of unanswered nudges | Required, default 0 |
| `created_at` | `datetime` | Conversation creation timestamp | Required |
| `trigger_id` | `str` | Original trigger that started this conversation | Required |
| `trigger_kind` | `str` | Cached trigger.kind for routing | Required |

**Invariants:**
- Once `ended = True`, state is immutable.
- `turns` cannot exceed 5.
- `nudge_count >= 3` triggers graceful end.
- `wait_until > now` blocks new sends in tick.

### 3.3 Turn (embedded in ConversationState.turns)

| Field | Type | Description |
|---|---|---|
| `from_role` | `str` | `merchant`, `customer`, or `vera` |
| `message` | `str` | The message content |
| `received_at` | `datetime` | Timestamp |
| `classification` | `str \| None` | Classification result (for incoming messages) |
| `bot_action` | `str \| None` | Bot's response action (`send`/`wait`/`end`) |
| `body_sent` | `str \| None` | Body of bot's response (if `send`) |
| `cta_sent` | `str \| None` | CTA of bot's response |
| `wait_seconds` | `int \| None` | Wait duration (if `wait`) |

### 3.4 SuppressionRegistry

```
suppression_registry: set[(merchant_id, suppression_key)]
```

| Operation | Description |
|---|---|
| `add((merchant_id, key))` | On action send |
| `contains((merchant_id, key))` | Pre-compose check |
| `cleanup_expired(trigger.expires_at)` | Periodic cleanup at tick start |

### 3.5 BodyHashRegistry

```
body_hash_registry: dict[conversation_id, set[body_hash]]
```

| Operation | Description |
|---|---|
| `add(conv_id, hash)` | On action send |
| `contains(conv_id, hash)` | Validation gate check #11 |

**Hash function:** SHA-256 of normalized body (lowercased, whitespace-collapsed, stripped of emoji).

### 3.6 TopicRegistry

```
topic_registry: dict[merchant_id, set[(trigger_kind, signal_id)]]
```

| Operation | Description |
|---|---|
| `add(merchant_id, (kind, signal_id))` | On action send |
| `contains(merchant_id, (kind, signal_id))` | Pre-compose filter |
| `get_topics(merchant_id)` | For conversation history leverage |

### 3.7 FreshContextRegistry

| Field | Type | Description |
|---|---|---|
| `key` | `tuple[str, str]` | `(scope, context_id)` |
| `latest_version` | `int` | Highest version seen |
| `pending` | `bool` | True if composer hasn't yet incorporated this version |
| `received_at` | `datetime` | When this version was pushed |

**Operations:**
- On `/v1/context` push: set `pending = True`, update `latest_version`.
- On successful composition that uses a fact from this version: set `pending = False`.

### 3.8 FactsRegistryEntry (transient, per compose call)

| Field | Type | Description |
|---|---|---|
| `numbers` | `set[str]` | All verifiable numbers from current context |
| `dates` | `set[str]` | All dates (ISO format) |
| `citations` | `set[str]` | Journal/authority names + issue/page |
| `names` | `set[str]` | Owner first names, merchant names, customer names |
| `prices` | `set[str]` | Offer prices from `offer_catalog` |
| `localities` | `set[str]` | Cities, localities |
| `computed` | `set[str]` | Pre-computed numbers (cohort counts, lapsed %) |

**Lifecycle:** Built fresh per compose call from current context versions. Discarded after validation.

## 4. Relationships & Integrity Invariants

| Invariant | Enforcement |
|---|---|
| Version monotonicity per `(scope, context_id)` | `/v1/context` version compare; 409 on stale |
| Healthz counts ⇔ store contents | Counts derived from `len()` at request time |
| Ended conversations immutable | `if conversation.ended: return 400` on `/v1/reply` |
| Cache keys include all four context versions | Hash includes `category_version`, `merchant_version`, `trigger_version`, `customer_version` |
| Body hash registry per conversation | Prevents verbatim repeats within conversation |
| Suppression registry per merchant | Prevents trigger-level dedup misses |
| Topic registry per merchant | Prevents topic fatigue |
| Composer always reads current context version | No context snapshot in conversation state |
| `fresh_context_registry.pending = True` until composer uses new-version fact | Validated by gate check #2 |

## 6. Validation Rules per Entity

| Entity | Validation rule | Enforcement |
|---|---|---|
| ContextRecord | `scope` in enum; `version >= 1`; `payload` ≤ 500 KB | `/v1/context` Pydantic schema |
| ConversationState | `turns` ≤ 5; `nudge_count >= 3` → end; `ended=True` immutable | State machine + reply brain |
| Action (outbound) | All required fields present; `customer_id` nullable not omitted; `cta` in enum; no URL in body | Validation gate + Pydantic |
| Reply response | `action` in {send, wait, end}; if wait, `wait_seconds ∈ {900, 1800, 3600}`; if end, `rationale` present | Pydantic schema |
| FactsRegistryEntry | All numbers/dates/citations/names trace to current context | Built from current context only |
| ResponseCacheEntry | Cache key includes all four context versions | Hash function definition |

## 7. Data Lifecycle & Privacy

| Stage | Lifecycle |
|---|---|
| Birth | Context pushed via `/v1/context`; stored in `context_store` |
| Use | Composer reads current version at call time |
| Snapshot | Every 30s, atomic write to `disk_snapshot.sutra` |
| Teardown | `/v1/teardown` wipes all stores, registries, cache, logs (except anonymized spend aggregate) |
| Retention | Test duration only; no persistence after teardown |

**Privacy rules (§23 compliance):**
- All payloads synthetic; treat as if real.
- No transmission to non-LLM external APIs.
- LLM providers may receive merchant/customer fields.
- No scraping real magicpin/Google data.
- Secrets (LLM API keys) via env vars only.
- All output for challenge only — not real merchant outreach.

## 9. Deliberate Omissions

| Omission | Reason |
|---|---|
| No users table | Single-tenant (one bot = one team); no auth needed |
| No payments table | No billing in test window; spend tracked in llm_ledger only |
| No multi-tenant tables | One bot per submission |
| No audit log table | Logs are file-based (JSONL); not queryable DB |
| No notifications table | No outbound notifications (bot is polled, doesn't push) |
| No feature flags table | All features hard-coded; no runtime toggle |
| No A/B test table | Determinism requires single variant; no A/B |
| No embeddings table | RAG rejected (ADR-04); direct lookup suffices |
