# AppFlow — Sutra

## 1. Global Application Flow

```
┌─────────────────────────────────────────────────────────────────────┐
│                        60-MINUTE TEST WINDOW                        │
│                                                                     │
│  T=0      Warmup: 255 context pushes, healthz verified              │
│  T=0..60  Tick every 5 sim-min (12 ticks total)                     │
│           Adaptive injections interleaved (new digests, shifts,     │
│           ~15 new triggers, surprise customer scopes)                │
│  T=60     Score report generated                                     │
│                                                                     │
│  Phase 4 (top-10 only, post-window): 3 standalone 5-turn replays    │
└─────────────────────────────────────────────────────────────────────┘
```

## 2. Warmup Flow

```
START
  │
  ▼
harness → GET /v1/healthz
  │
  ▼ Sutra returns counts = 0/0/0/0 (initial empty state)
  │
harness → POST /v1/context × 255 (5 categories + 50 merchants + 200 customers)
  │
  ▼ Sutra: for each push:
  │   - validate scope ∈ {category, merchant, customer, trigger}
  │   - validate payload size ≤ 500 KB
  │   - if version > stored or new key: atomic replace, mark fresh_context_pending=True
  │   - if version == stored: no-op ack
  │   - if version < stored: 409 stale_version
  │   - respond 200 within 100ms
  │
harness waits 60s (settle)
  │
  ▼
harness → GET /v1/healthz
  │
  ▼ Sutra: counts derived from store = {category:5, merchant:50, customer:200, trigger:0}
  │
  ▼ if counts match pushed: warmup PASS
  │ if mismatch: warmup FAIL → 3-strike disqualification risk
  │
END WARMUP
```

**Failure handling:**
- If any context push returns 4xx/5xx: harness retries; if persistent, warmup fails.
- If healthz counts don't match: harness may flag; 3 consecutive failures → disqualification.
- Sutra's defense: counts always from live store; atomic writes; no static counters.

## 3. Context Push Flow

```
POST /v1/context {scope, context_id, version, payload, delivered_at}
  │
  ▼
┌─────────────────────────────────────────────┐
│  VALIDATION                                 │
│  - Content-Length ≤ 500 KB?  No → 400       │
│  - scope valid?              No → 400       │
│  - payload schema valid?     No → 400       │
└─────────────────────────────────────────────┘
  │ Yes
  ▼
┌─────────────────────────────────────────────┐
│  VERSION COMPARE                            │
│  stored = context_store.get((scope, ctx_id))│
│                                             │
│  if stored is None:                         │
│    → store new, mark fresh, 200 ack         │
│  elif version > stored.version:             │
│    → atomic replace, mark fresh, 200 ack    │
│  elif version == stored.version:            │
│    → no-op, 200 ack                        │
│  elif version < stored.version:             │
│    → 409 stale_version with current_v      │
└─────────────────────────────────────────────┘
  │
  ▼
fresh_context_registry[(scope, ctx_id)] = {
  latest_version: version,
  pending: True,  // composer will check this on next tick/reply
  received_at: now
}
  │
  ▼
200 {accepted: true, ack_id, stored_at}
```

**Atomic replace implementation:**
- Single-threaded write (uvicorn single worker); or asyncio.Lock around store mutation.
- Replace `context_store[(scope, ctx_id)]` with new `{version, payload, received_at}` in single assignment.
- Healthz counts derived at request time; no separate counter to drift.

## 4. Tick Decision Flow

```
POST /v1/tick {now, available_triggers: [...]}
  │
  ▼
┌─────────────────────────────────────────────────────────────┐
│  PHASE 1: FILTER                                            │
│  for each trigger_id in available_triggers:                 │
│    trigger = context_store.get(("trigger", trigger_id))     │
│    if trigger is None: skip                                 │
│    if trigger.expires_at < now: skip (expired)             │
│    if (merchant_id, suppression_key) in suppression_registry: skip
│    if (merchant_id, (kind, signal_id)) in topic_registry: skip
│    if conversation in wait_state (wait_until > now): skip   │
│    if merchant unsubscribed_from_topic: skip                │
└─────────────────────────────────────────────────────────────┘
  │
  ▼ filtered_triggers list
┌─────────────────────────────────────────────────────────────┐
│  PHASE 2: SCORE & RANK                                      │
│  for each (merchant, trigger) in filtered:                  │
│    score = trigger.urgency (1-5)                            │
│          × freshness_factor (1.5 if fresh_context_pending else 1.0)
│          × merchant_priority (1.0 default; 1.2 if verified)│
│    rank by score desc                                       │
└─────────────────────────────────────────────────────────────┘
  │
  ▼ ranked list
┌─────────────────────────────────────────────────────────────┐
│  PHASE 3: TOP-K SELECTION                                   │
│  top_k = min(5, len(ranked))  // 3-5 parallel budget        │
│  selected = ranked[:top_k]                                  │
└─────────────────────────────────────────────────────────────┘
  │
  ▼
┌─────────────────────────────────────────────────────────────┐
│  PHASE 4: PARALLEL COMPOSITION                             │
│  async: for each (merchant, trigger) in selected:          │
│    action = compose_pipeline(merchant, trigger, customer)  │
│    (see Composer Pipeline Flow)                             │
│  await all (with 25s budget per call)                       │
└─────────────────────────────────────────────────────────────┘
  │
  ▼ actions list (some may be None if validation rejected + fallback failed)
┌─────────────────────────────────────────────────────────────┐
│  PHASE 5: ASSEMBLE & RETURN                                 │
│  actions = [a for a in actions if a is not None][:20]       │
│  for each action: write to suppression_registry,            │
│    body_hash_registry, topic_registry                       │
│  return {actions: [...]}                                    │
└─────────────────────────────────────────────────────────────┘
```

**Restraint:** If filtered list is empty OR no action passes validation, return `{"actions": []}`. Empty is always valid.

## 5. Composer Pipeline Flow

```
compose_pipeline(merchant, trigger, customer=None)
  │
  ▼
┌──────────────────────────────────────────────────────────────┐
│  STEP 1: ROUTER                                              │
│  variant = router(trigger.kind, trigger.scope)               │
│  → one of 15 variants (see TechSpec AI-1)                    │
└──────────────────────────────────────────────────────────────┘
  │
  ▼
┌──────────────────────────────────────────────────────────────┐
│  STEP 2: FACTS REGISTRY EXTRACTION                           │
│  facts = extract_facts(                                       │
│    category = current category context,                      │
│    merchant = current merchant context,                      │
│    trigger = current trigger context,                        │
│    customer = current customer context (if any)              │
│  )                                                            │
│  // extracts numbers, dates, citations, names, prices,       │
│  //    localities, computed numbers (e.g., cohort counts)    │
└──────────────────────────────────────────────────────────────┘
  │
  ▼
┌──────────────────────────────────────────────────────────────┐
│  STEP 3: CACHE CHECK                                         │
│  cache_key = hash(category_id, category_version,             │
│                  merchant_id, merchant_version,              │
│                  trigger_id, trigger_version,                 │
│                  customer_id, customer_version,              │
│                  language)                                    │
│  if cache_key in response_cache:                             │
│    return cached action (byte-identical)                     │
└──────────────────────────────────────────────────────────────┘
  │ miss
  ▼
┌──────────────────────────────────────────────────────────────┐
│  STEP 4: SYSTEM PROMPT ASSEMBLY                              │
│  prompt = assemble_prompt(                                    │
│    variant, voice_profile, language, cta_policy,             │
│    judgment_hook, taboo_list, required_vocab,               │
│    "no URLs" rule, "single CTA in last sentence" rule        │
│  )                                                            │
└──────────────────────────────────────────────────────────────┘
  │
  ▼
┌──────────────────────────────────────────────────────────────┐
│  STEP 5: LLM CALL (25s hard timeout)                         │
│  try primary:                                                 │
│    response = primary_llm.complete(prompt, temp=0, top_p=1)  │
│  except (timeout, 5xx, connection):                          │
│    try secondary:                                             │
│      response = secondary_llm.complete(prompt, temp=0)      │
│    except:                                                    │
│      response = None  // fall to fallback template           │
└──────────────────────────────────────────────────────────────┘
  │
  ▼
┌──────────────────────────────────────────────────────────────┐
│  STEP 6: VALIDATION GATE (13 checks, enforced order)         │
│  if response is None: skip to fallback template              │
│  for check in [url_scan, facts_membership, single_cta,        │
│                cta_in_last_sentence, cta_policy_match,      │
│                taboo_scan, domain_vocab, language_match,     │
│                owner_name_greeting, min_facts, body_hash,    │
│                plagiarism_check, rationale_subset]:          │
│    if not check(response, facts, conversation_state):       │
│      // re-prompt ONCE with stricter instruction             │
│      stricter_prompt = add_stricture(prompt, failed_check)   │
│      response = primary_llm.complete(stricter_prompt)       │
│      if not check(response, ...):                            │
│        response = None  // fall to fallback template         │
│      break                                                    │
└──────────────────────────────────────────────────────────────┘
  │
  ▼
┌──────────────────────────────────────────────────────────────┐
│  STEP 7: FALLBACK TEMPLATE (if response is None)             │
│  template = fallback_templates[(trigger.kind, scope,        │
│                                  category.slug)]             │
│  action = template.fill(facts, language)                     │
│  // always produces valid action (no LLM dependency)         │
└──────────────────────────────────────────────────────────────┘
  │
  ▼
┌──────────────────────────────────────────────────────────────┐
│  STEP 8: CACHE WRITE                                          │
│  response_cache[cache_key] = action                          │
│  return action                                                │
└──────────────────────────────────────────────────────────────┘
```

## 6. Reply Handling Flow

```
POST /v1/reply {conversation_id, merchant_id, customer_id, from_role, message, turn_number}
  │
  ▼
┌──────────────────────────────────────────────────────────────┐
│  STEP 1: APPEND TURN                                          │
│  conversation = conversation_store[conversation_id]          │
│  conversation.turns.append({from_role, message, received_at})│
│  if from_role in {merchant, customer}:                       │
│    conversation.last_merchant_reply_at = received_at          │
└──────────────────────────────────────────────────────────────┘
  │
  ▼
┌──────────────────────────────────────────────────────────────┐
│  STEP 2: CLASSIFY                                             │
│  class = classifier(message, conversation.turns)             │
│  // regex-first; LLM tiebreaker only if multi-match          │
│  // returns one of:                                           │
│  //   accept, question, objection, auto_reply,               │
│  //   explicit_intent, hostile, off_topic                     │
└──────────────────────────────────────────────────────────────┘
  │
  ▼
┌──────────────────────────────────────────────────────────────┐
│  STEP 3: STATE MACHINE                                         │
│  switch class:                                                │
│    case accept:                                               │
│      → action mode (verbs: done, sending, drafting, confirm) │
│      → compose reply via composer pipeline (action variant)  │
│      → return {action: send, body, cta, rationale}           │
│                                                               │
│    case question:                                             │
│      → answer the question from context                      │
│      → re-pitch original CTA                                  │
│      → return {action: send, body, cta, rationale}          │
│                                                               │
│    case objection:                                            │
│      → acknowledge ("Samajh gaya")                            │
│      → counter-offer (different angle or wait)               │
│      → if 2nd objection: return {action: end, rationale}     │
│      → else: return {action: send, body, cta, rationale}     │
│                                                               │
│    case auto_reply:                                           │
│      → if first detection:                                   │
│          send one explicit prompt ("owner se directly        │
│          connect karne ki koshish karungi?")                  │
│          → return {action: wait, wait_seconds: 1800, ...}    │
│      → if second detection (post-wait):                      │
│          → return {action: end, rationale: "auto-reply       │
│            detected 3×; gracefully exiting"}                 │
│                                                               │
│    case explicit_intent:                                      │
│      → switch to ACTION MODE immediately                      │
│      → compose: "Done — sending X now" or "Drafting Y,      │
│        will share in 10 min" or "Confirming Z"               │
│      → NEVER another qualifying question                      │
│      → return {action: send, body, cta, rationale}           │
│                                                               │
│    case hostile:                                              │
│      → return {action: end, rationale:                       │
│        "merchant requested stop; gracefully exiting"}         │
│                                                               │
│    case off_topic:                                            │
│      → compose: "Yeh mission ke bahar hai, but main aapke    │
│        GBP/account par focus kar sakti hoon. Want me to      │
│        continue with X?"                                     │
│      → return {action: send, body, cta, rationale}          │
│      → OR if 2nd off-topic: return {action: end, ...}        │
└──────────────────────────────────────────────────────────────┘
  │
  ▼
┌──────────────────────────────────────────────────────────────┐
│  STEP 4: TURN BUDGET CHECK                                    │
│  if turn_number == 4 and not mid-transaction:                │
│    → compose wind-down: "Aap busy lagte hain. Main baad      │
│      mein follow up karungi. Best wishes!"                   │
│    → return {action: end, rationale: "5-turn cap; graceful   │
│      exit"}                                                   │
│  if nudge_count >= 3 unanswered:                             │
│    → return {action: end, rationale: "3 unanswered; backing  │
│      off"}                                                    │
└──────────────────────────────────────────────────────────────┘
```

## 7. Replay Scenario Flows (Phase 4, top-10 only)

### 7.1 Auto-reply hell (4 identical canned auto-replies)

```
Turn 1 (Sutra outbound): "Dr. Meera, JIDA's Oct issue landed..."
Turn 2 (harness): "Aapki jaankari ke liye bahut-bahut shukriya. Main aapki
                  yeh sabhi baatein aur sujhaav hamari team tak pahuncha
                  deti hoon."  [auto-reply signature]
  │
  ▼ Sutra: classifier detects signature "bahut-bahut shukriya" + "team tak pahuncha"
  │       auto_reply class
  ▼ Send one explicit prompt (flag-once):
    "Samajh gayi. Team tak pahunchane se pehle, kya aap khud dekhna
     chahingi ki exact kya missing hai Google pe? 2 minute ka kaam hai.
     Chalega?"
  │
  ▼ return {action: send, ...}

Turn 3 (harness): same verbatim auto-reply  [2nd detection]
  │
  ▼ Sutra: verbatim match with Turn 2 (1st repeat)
  ▼ Continue conversation but signal suspicion
  ▼ return {action: wait, wait_seconds: 1800, rationale:
           "Suspected auto-reply; backing off 30 min"}

Turn 4 (harness, after wait): same verbatim auto-reply  [3rd detection]
  │
  ▼ Sutra: verbatim 3× → confirmed auto_reply
  ▼ return {action: end, rationale:
           "Auto-reply confirmed (3× verbatim); gracefully exiting"}

[No further turns]
```

### 7.2 Intent transition ("ok let's do it. Whats next?")

```
Turn 1 (Sutra outbound): "Dr. Meera, your CTR is 2.1% vs 3.0% peer median.
                         You already have Dental Cleaning @ ₹299. Want me
                         to draft a 160-char patient message around it?"
Turn 2 (harness): "Ok let's do it. Whats next?"
  │
  ▼ Sutra: classifier detects "let's do it" → explicit_intent class
  ▼ State machine: action mode immediately
  ▼ Compose: "Done — drafting now. Will share a 160-char patient-ed
              WhatsApp around 'Dental Cleaning @ ₹299' in 10 min. Also
              adding your high-risk-adult cohort filter (78 lapsed
              >180 days). Reply STOP if you'd rather pause."
  │
  ▼ return {action: send, body, cta: "binary_yes_no", rationale:
           "Intent detected; switched to action mode; CTA binary to
            confirm or pause"}

[NO further qualifying questions like "would you like..." or "do you..."]
```

### 7.3 Hostile & off-topic

```
Turn 1 (Sutra outbound): "Suresh, 6,777 people in Sector 14 searched
                         for makeup services last month but didn't find

                         appear?"

  ▼ Sutra: classifier detects "stop messaging me" → hostile class
  │       (off_topic ask is secondary; hostile takes precedence)
  ▼ State machine: hostile → polite end

```

## 8. Success Definition

A flow is **successful** when:
1. It completes within the latency budget (tick <25s, reply <10s, context <100ms).
2. It returns a valid schema-conformant response.
3. The action/body/rationale pass all 13 validation gate checks.
4. No URL appears in any body.
5. No verbatim repeat of any prior body in the same conversation.
6. The conversation ends gracefully (not via 5-turn cap cutoff) when appropriate.
7. Adaptive injections are visibly incorporated in subsequent compositions.

## 9. Failure Flows

### 9.1 LLM slow / down mid-tick

```
tick fires → composer pipeline → LLM call (primary)
  │
  ▼ 25s timeout
  ▼ catch timeout
  ▼ try secondary provider
  │   ├── success → validate → return action
  │   └── fail → fallback template
  ▼
return action (template-based if needed)
```

### 9.2 Quota hit mid-window

```
spend_meter checks before each LLM call
  │
  ▼ if spend >= $25:
      switch to fallback-only mode
      all subsequent compositions use templates only
      log: "fallback-only mode activated; spend=$25"
  │
  ▼ if spend >= $20 (soft alert):
      log: "soft alert; spend=$20"
      continue with LLM
```

### 9.3 Host restart mid-test

```
host restarts (crash / deploy / cloud auto-restart)
  │
  ▼ on startup:
  │   - check for disk_snapshot.sutra
  │   - if present: load state from snapshot (≤30s stale)
  │   - if absent: start fresh (state lost; healthz counts will rebuild
  │     as harness re-pushes? — actually no, harness doesn't re-push
  │     on restart; state is gone for the test duration)
  │
  ▼ healthz counts derived from recovered state
  ▼ bot resumes serving
  │
  ▼ if recovery >60s: harness healthz poll fails 1-2×
      (acceptable if <3 consecutive; 3-strike only on 3 consecutive)
```

### 9.4 Validation gate too strict (rejects everything)

```
validation_rejection_rate > 50%
  │
  ▼ log alert
  ▼ switch to fallback-only mode (templates)
  ▼ log: "validation over-rejecting; fallback-only mode activated"
  │
  ▼ templates score 5-7/dim (lower but non-zero, no penalties)
```

## 10. Edge Cases Table

| Edge case | Handling |
|---|---|
| Unseen merchant pushed mid-conversation | Treat as normal new merchant; composer reads current context version at call time; no special handling |
| Language switch mid-conversation (English → Hindi) | Update conversation.language on next turn classification; subsequent compositions use new language; cached responses for old language invalidated |
| Expired trigger in `available_triggers` | Filter in tick Phase 1: `if trigger.expires_at < now: skip` |
| Wait expiry re-engage | On tick, check `wait_until <= now` for waiting conversations; re-engage with new action (not the same as the waited-on one) |
| 5-turn cap wind-down | At turn 3, start closing; at turn 4, end gracefully unless mid-transaction |
| Duplicate context push (same version) | No-op; 200 ack with same `ack_id` |
| Unknown scope in `/v1/context` | 400 `invalid_scope` |
| Payload > 500 KB | 400 `payload_too_large` |
| Conversation in `wait` state receives `/v1/reply` | Process the reply (merchant broke the wait); classify and respond |
| Conversation `ended` receives `/v1/reply` | Return 400 `conversation_ended`; do not re-engage |
| `customer_id` null in `/v1/tick` action | Send-as = `vera`; merchant-facing |
| `customer_id` present in `/v1/tick` action | Send-as = `merchant_on_behalf`; check `consent.scope` before composing |
| Multiple merchants in `available_triggers` (multi-merchant tick) | Rank across all; pick top 3-5 across merchants by score |
| Trigger kind not in routing table | Use generic `dormant_reengage` variant as fallback; log warning |
| LLM returns malformed JSON | Parse error → treat as LLM failure → secondary → templates |
| LLM returns body > 4096 chars | Truncate at sentence boundary; re-validate |
| Owner first name absent | Use merchant name; if also absent, use locality-based greeting ("Lajpat Nagar clinic") |
| Customer consent scope doesn't cover trigger kind | Skip action; do not compose |

## 11. State Machines

### 11.1 Conversation lifecycle

```
                    ┌─────────┐
                    │  NEW    │  (created in /v1/tick)
                    └────┬────┘
                         │ first send
                         ▼
                    ┌─────────┐
              ┌────►│ ACTIVE  │◄──── merchant reply (/v1/reply)
              │     └────┬────┘
              │          │
              │          ├──► wait_seconds ──►┐
              │          │                    │
              │          ▼                    ▼
              │     ┌─────────┐         ┌─────────┐
              │     │ WAITING │ ──────►│ ACTIVE  │ (wait expired, next tick)
              │     └────┬────┘         └─────────┘
              │          │ merchant reply during wait
              └──────────┘
                         │
                         ├──► 5-turn cap
                         ├──► 3 unanswered nudges
                         ├──► hostile classification
                         ├──► 2nd objection
                         ├──► auto-reply confirmed (3×)
                         ├──► repeated off-topic
                         ▼
                    ┌─────────┐
                    │ ENDED   │  (immutable; no further sends)
                    └─────────┘
```

### 11.2 Classifier transitions

```
                        ┌────────────────────┐
                        │ incoming message    │
                        └─────────┬──────────┘
                                  │
                                  ▼
                        ┌────────────────────┐
                        │ regex classifier   │
                        └─────────┬──────────┘
                                  │
                  ┌───────────────┼───────────────┐
                  │               │               │
            single match    multi-match        no match
                  │               │               │
                  ▼               ▼               ▼
            return class    LLM tiebreaker    class = accept
                              (rare)
```
