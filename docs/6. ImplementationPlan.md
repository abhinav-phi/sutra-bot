## 2. Phase 2 — Deterministic Layer (6h)

**Goal:** Facts registry extraction + ~60 fallback templates; bot can produce sensible actions without any LLM.

**Tasks:**
- Implement `FactsRegistry` extraction (`composer/facts_registry.py`)
  - Walk category, merchant, trigger, customer contexts
  - Extract: numbers, dates, citations (incl. `professional_journals`/`regulatory_authorities`), names, prices, localities
  - Compute derived numbers: cohort counts from `customer_aggregate`, lapsed %, peer gaps
- Implement ~60 fallback templates (`composer/fallback_templates.py`)
  - 15 trigger kinds × 2 scopes × ~5 categories (some shared)
  - Each template: owner first name, one verifiable number, single CTA, correct language, vertical voice
- Wire fallback templates into `/v1/tick` (replace stub)
- Test: kill LLM keys; verify tick returns sensible actions from templates

**Dependencies:** Phase 1.

**Hour estimate:** 6h.

**Exit criteria:**
- [ ] `FactsRegistry` extracts all numbers/dates/citations from sample context
- [ ] 60 fallback templates implemented
- [ ] With LLM keys removed, `/v1/tick` returns sensible actions
- [ ] Each fallback template passes: owner name present, ≥1 verifiable number, single CTA, correct vertical voice, no URLs

## 3. Phase 3 — Validation Gate (3h)

**Goal:** 13-check validation gate in enforced order.

**Tasks:**
- Implement `ValidationGate` (`composer/validation_gate.py`)
- Implement each of 13 checks in order:
  1. URL scan (regex)
  2. Facts membership (every number/date/citation/name traces)
  3. Single CTA (no multiple-CTA patterns)
  4. CTA in last sentence
  5. CTA policy matches trigger.kind
  6. Taboo word scan (per-vertical)
  7. Domain vocab presence (≥1 vertical word)
  8. Language match
  9. Owner first name greeting
  10. ≥4-5 verifiable facts woven
  11. Body-hash anti-repetition
  12. Plagiarism check (Jaccard <0.6 vs case studies)
  13. Rationale facts ⊆ body facts
- Implement re-prompt-once logic (stricter instruction)
- Implement fallback-on-second-fail logic
- Log every rejection with reason code

**Dependencies:** Phase 2.

**Hour estimate:** 3h.

**Exit criteria:**
- [ ] All 13 checks implemented and tested individually
- [ ] URL injection in LLM output → rejected
- [ ] Fabricated number in LLM output → rejected
- [ ] Multiple CTAs → rejected
- [ ] Taboo word (e.g., "cure" for dentists) → rejected
- [ ] Language mismatch → rejected
- [ ] Rejection rate logged; threshold alert at >50%

## 4. Phase 4 — LLM Composer + Router + Cache + Three-Tier Fallback (6h)

**Goal:** Full composer pipeline operational; LLM-composed messages pass validation gate.

**Tasks:**
- Implement Router (`composer/router.py`) — 15 kind × 2 scope → variant
- Implement 15 system prompt variants (`composer/prompts.py`)
  - Voice profile per vertical
  - Language instruction
  - CTA policy per trigger.kind
  - Judgment hook (contrarian allowed) for `festival_upcoming`, `perf_spike`, `perf_dip`, `weather_heatwave`
  - Taboo list per vertical
  - Required vocab list per vertical
  - "No URLs" rule
  - "Single CTA in last sentence" rule
- Implement multi-provider LLM client (`llm/client.py`)
  - Primary (Anthropic) → Secondary (OpenAI) → fallback templates
  - 25s hard timeout per call
  - temp=0, top_p=1
- Implement response cache (`composer/cache.py`)
  - Hash key: (category_id+version, merchant_id+version, trigger_id+version, customer_id+version, language)
- Implement LLM ledger (`llm/ledger.py`) — log every call
- Wire composer pipeline into `/v1/tick` (replace fallback-only)
- Test: tick returns LLM-composed actions that pass validation gate

**Dependencies:** Phase 3.

**Hour estimate:** 6h.

**Exit criteria:**
- [ ] Router selects correct variant for all 15 trigger kinds
- [ ] LLM primary call succeeds within 25s
- [ ] On primary timeout/error, secondary fires within budget
- [ ] On secondary fail, fallback template used
- [ ] Cache hit returns byte-identical response
- [ ] LLM-composed messages pass all 13 validation checks (or re-prompt succeeds)
- [ ] Spend meter logs every call

## 5. Phase 5 — Tick Orchestration (4h)

  - `last_merchant_reply_at` field
  - Template vs free-form decision per action
- Implement restraint logic (skip if no qualifying trigger)
- Implement `fresh_context_registry` updates on context push

**Dependencies:** Phase 4.

**Hour estimate:** 4h.

**Exit criteria:**
- [ ] Tick filters expired triggers (verify expired trigger in `available_triggers` is skipped)
- [ ] Tick ranks by score (verify top-K selection)
- [ ] Parallel composition completes within 25s budget for 5 actions
- [ ] Suppression registry prevents duplicate sends

## 6. Phase 6 — Reply Brain + Replay Tests (5h)

**Goal:** Heuristic classifier + state machine; all 3 Phase 4 replay scenarios pass.

**Tasks:**
- Implement heuristic classifier (`reply/classifier.py`)
  - 7 classes: accept, question, objection, auto_reply, explicit_intent, hostile, off_topic
  - Regex patterns incl. Hindi/Hinglish signatures
  - LLM tiebreaker for multi-match (rare)
- Implement state machine (`reply/state_machine.py`)
  - accept → action mode
  - question → answer + re-pitch
  - objection → acknowledge + counter-offer or end
  - auto_reply → flag-once → wait 1800s → end
  - explicit_intent → action mode immediately (action verbs)
  - hostile → polite end
  - off_topic → decline + redirect or end
- Implement turn budget management (wind down by turn 3-4)
- Implement nudge count tracking (end after 3 unanswered)
- Wire reply brain into `/v1/reply` (replace stub)
- Build adversarial replay test scripts (`tests/test_adversarial_replays.py`)
  - auto_reply_hell: 4 identical canned auto-replies → assert detect → wait → end
  - intent_transition: "ok let's do it" → assert action-mode verbs, zero qualifying questions
  - hostile: "stop messaging me" → assert `action: end`
  - off_topic: "file GST" → assert decline + redirect

**Dependencies:** Phase 5.

**Hour estimate:** 5h.

**Exit criteria:**
- [ ] Classifier correctly classifies all 7 classes on test patterns
- [ ] Auto-reply hell: bot sends 1 explicit prompt → wait → end (≤2 sends after detection)
- [ ] Intent transition: bot's response contains action-mode verbs (done/sending/drafting/confirm); ZERO "would you"/"do you"
- [ ] Hostile: bot returns `action: end`
- [ ] Off-topic: bot declines + redirects or ends
- [ ] Turn budget: bot winds down by turn 3-4; ends before 5-turn cap unless mid-transaction

## MVP Cut Line — Never Cut

These are operational floor. Cutting any = submission fails or scores poorly regardless of other features:

- **Validation gate** (all 13 checks) — prevents URL (−3), hallucination (cap 5), multiple CTA, repeat (−2)
- **Fallback templates** — bot never silent when LLM down
- **Healthz from store** — prevents −10 + disqualification
- **Atomic context store** — prevents stale composition, lost adaptation bonus
- **Suppression registries** — prevents verbatim repeat (−2 + cap 5)
- **URL scan in validation gate** — prevents −3/URL hard fail
- **Schema conformance (Pydantic)** — prevents −2/action malformed
- **Idempotent context (409 stale, 400 malformed)** — operational correctness
- **Single CTA in last sentence** — prevents Engagement penalty
